# Postman 测试样例（V7 完整流程）

本文档配合 Postman 的 **中文测试集合** 使用，按“从 0 到 1 的业务链路”把每个环节说明清楚，并给出建议执行顺序。

## 1. 你将导入的文件

### 1.1 Postman 集合（中文命名）

- 文件：[高校知识产权运营服务平台_API_V7_测试样例.postman_collection.json](file:///d:/patent/patent/postman/%E9%AB%98%E6%A0%A1%E7%9F%A5%E8%AF%86%E4%BA%A7%E6%9D%83%E8%BF%90%E8%90%A5%E6%9C%8D%E5%8A%A1%E5%B9%B3%E5%8F%B0_API_V7_%E6%B5%8B%E8%AF%95%E6%A0%B7%E4%BE%8B.postman_collection.json)

### 1.2 Postman 环境（中文变量）

- 文件：[高校知识产权运营服务平台_API_V7_本地环境.postman_environment.json](file:///d:/patent/patent/postman/%E9%AB%98%E6%A0%A1%E7%9F%A5%E8%AF%86%E4%BA%A7%E6%9D%83%E8%BF%90%E8%90%A5%E6%9C%8D%E5%8A%A1%E5%B9%B3%E5%8F%B0_API_V7_%E6%9C%AC%E5%9C%B0%E7%8E%AF%E5%A2%83.postman_environment.json)

环境变量说明：

| 变量名 | 说明 |
| --- | --- |
| 主机/端口 | 服务地址，例如 localhost + 8080 |
| 用户名/密码 | 注册与登录使用（集合会自动生成用户名） |
| token | 登录后自动写入，后续接口自动带上 `Authorization: Bearer {{token}}` |
| 用户ID/个人专利ID/需求ID/机构ID/通知ID/同步任务ID | 创建资源后自动写入，用于后续链路接口 |

## 2. 执行前准备（必须）

1. 启动后端服务（确保能访问 `{{主机}}:{{端口}}`）。
2. 在 Postman 中选择环境：`高校知识产权运营服务平台 - 本地环境（V7）`
3. 确认 `主机` 与 `端口` 填写正确。

填写规范：

| 字段 | 正确示例 | 错误示例 | 原因 |
| --- | --- | --- | --- |
| 主机 | localhost / 127.0.0.1 / 192.168.1.10 / api.xxx.com | http://localhost / https://api.xxx.com | 主机变量里不要包含协议前缀，否则会导致 Host 头非法 |
| 端口 | 8080 / 80 / 443 | :8080 / 80/ | 只填数字 |

请求网址说明：

| 场景 | 主机/端口 建议值 | 例子 |
| --- | --- | --- |
| 本地启动 | localhost + 8080 | 实际请求：`localhost:8080/api/auth/login` |
| 测试/生产 | <your-domain> + 443(或实际端口) | 实际请求：`<your-domain>:443/api/users/me` |

## 3. 推荐执行顺序（按环节跑通）

### 3.1 环节 A：准备随机账号

1. 执行：`00-准备工作 / 00.01 设置随机账号（自动）`
2. 结果：环境变量 `用户名` 与 `密码` 会写入（密码默认为 123456）。

### 3.2 环节 B：注册 + 登录（获取 token）

1. 执行：`01-认证模块（注册/登录） / 01.01 注册（写入用户ID）`
   - 结果：`用户ID` 写入环境变量
2. 执行：`01-认证模块（注册/登录） / 01.02 登录（写入token）`
   - 结果：`token` 写入环境变量

如果后续接口返回 401，优先检查：
- 是否已选择环境
- `token` 是否非空
- `baseUrl` 是否正确

### 3.3 环节 C：用户模块（获取我的信息 / 更新资料）

1. 执行：`02-用户模块（我的信息/更新资料） / 02.01 获取当前用户信息（/api/users/me）`
2. 执行：`02-用户模块（我的信息/更新资料） / 02.02 更新用户资料（/api/users/me/profile）`

### 3.4 环节 D：公共专利库（查询/写入/详情）

1. 执行：`03-公共专利库（查询/写入/查看详情） / 03.01 查询专利（wind，分页）`
2. 执行：`03-公共专利库（查询/写入/查看详情） / 03.02 写入/更新专利（wind，CN_TEST_001）`
3. 执行：`03-公共专利库（查询/写入/查看详情） / 03.03 获取单条专利详情（wind/CN_TEST_001）`

### 3.5 环节 E：个人专利管理（上传→列表→详情→更新→删除）

1. 执行：`04-个人专利管理（上传/列表/详情/更新/删除） / 04.01 上传个人专利（写入个人专利ID）`
   - 结果：`个人专利ID` 写入环境变量
2. 执行：`04.02 查看我的专利列表（owner=me）`
3. 执行：`04.03 查看专利详情（个人专利ID）`
4. 执行：`04.04 更新个人专利（改为PRIVATE）`
5. 执行：`04.05 删除个人专利（清理）`

说明：
- “更新改为 PRIVATE”后，非本人用户访问该记录会被拒绝（403）。

### 3.6 环节 F：专家模块（查询/提交认证/管理员录入/管理员审核）

1. 执行：`05-专家模块（查询/提交认证/管理员录入/管理员审核） / 05.01 查询专家（公开）`
2. 执行：`05.02 提交专家认证（当前用户）`
3. 需要“管理员模拟录入/审核”时执行：
   - `05.03 管理员录入专家（POST /api/experts）`
   - `05.04 管理员审核专家（/api/admin/experts/{userId}/audit）`

说明：
- 当前项目未实现 RBAC 权限区分，因此“管理员接口”默认只要登录即可调用（便于联调）。

### 3.7 环节 G：需求与匹配（创建→匹配→保存结果）

1. 执行：`06-需求与匹配（创建需求/匹配/保存结果） / 06.01 创建需求（写入需求ID）`
   - 结果：`需求ID` 写入环境变量
2. 执行：`06.02 需求匹配专利`
3. 执行：`06.03 需求匹配专家`
4. 执行：`06.04 保存专利匹配结果`
5. 执行：`06.05 保存专家匹配结果`

### 3.8 环节 H：转化成果（查询/创建）

1. 执行：`07-转化成果（查询/创建） / 07.01 查询转化成果列表`
2. 执行：`07.02 创建转化成果记录`

### 3.9 环节 I：价值评估（生成/查询/参数维护）

1. 执行：`08-价值评估（生成报告/查询报告/维护参数） / 08.01 生成评估报告（EXTERNAL）`
2. 执行：`08.02 查询评估报告列表（EXTERNAL）`
3. 执行：`08.03 维护评估模型参数（PUT /api/valuation-params/{key}）`

### 3.10 环节 J：机构（创建/查询/加入）

1. 执行：`09-机构（创建/查询/加入） / 09.01 创建机构（写入机构ID）`
   - 结果：`机构ID` 写入环境变量
2. 执行：`09.02 查询机构（query=测试）`
3. 执行：`09.03 加入机构/设置主机构`

### 3.11 环节 K：通知（列表/创建/已读）

1. 执行：`10-通知（列表/创建/已读） / 10.01 查询通知列表`
2. 执行：`10.02 创建通知（写入通知ID）`
   - 结果：`通知ID` 写入环境变量
3. 执行：`10.03 标记通知已读`

### 3.12 环节 L：审计日志（查询）

1. 执行：`11-审计日志（查询） / 11.01 查询审计日志（action包含login）`

### 3.13 环节 M：数据同步任务（创建/列表/详情）

1. 执行：`12-数据同步任务（创建/列表/详情） / 12.01 创建同步任务（写入任务ID）`
   - 结果：`同步任务ID` 写入环境变量
2. 执行：`12.02 查询任务列表（mine=true）`
3. 执行：`12.03 查询任务详情（任务ID）`

### 3.14 环节 N：AI 问答（通义千问后端中转）

前置条件：

- 服务端已配置环境变量 `DASHSCOPE_API_KEY`（只在后端保存，前端不接触）

执行步骤：

1. 先完成“登录”（确保 `token` 有值）
2. 执行：`12 AI（通义千问中转） / 12.01 AI问答（后端中转）`

### 3.15 环节 O：聊天会话（持久化，登录后继续对话）

执行步骤：

1. 先完成“登录”（确保 `token` 有值）
2. 执行：`13 聊天会话（持久化） / 13.01 创建会话（写入：会话ID）`
3. 执行：`13.04 继续对话（带历史上下文）`（可重复执行多次）
4. 执行：`13.03 查询会话消息记录（会话ID）`（用于前端展示历史记录）

### 3.16 环节 P：专利 ES 检索（关键词/关键语句/全文）

前置条件：

- 已部署 Elasticsearch
- 后端已启用 ES：设置环境变量 `ES_ENABLED=true`，并配置 `ES_URIS`（例如 `http://localhost:9200`）

执行步骤：

1. 先完成“登录”（用于重建索引的 POST 请求）
2. 执行：`14 专利ES搜索（Elasticsearch） / 14.01 重建ES索引（全部，需登录）`（首次必做）
3. 执行：`14.03 ES检索（关键词，多字段）` 或 `14.04 ES检索（关键语句，phrase=true）`

## 4. 常见问题（排错）

### 4.1 401 未授权
- 先确认是否执行过“登录”，并且环境变量 `token` 有值。
- 确认请求 Header 是否带了 `Authorization: Bearer {{token}}`。

### 4.2 400 参数错误
- 对照接口文档检查必填参数是否齐全：[api_v7_项目书全量接口文档.md](file:///d:/patent/patent/docs/api_v7_%E9%A1%B9%E7%9B%AE%E4%B9%A6%E5%85%A8%E9%87%8F%E6%8E%A5%E5%8F%A3%E6%96%87%E6%A1%A3.md)

### 4.3 403 无权限
- 个人专利被改为 PRIVATE 后，只有本人可访问。
